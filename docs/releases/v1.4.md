不常驻的 Windows 桌面工具：把 Clash Verge Rev 订阅里的节点各自开放成一个本地代理端口。

## 下载

- **PortPilot-v1.4-windows-amd64.exe** —— 单个文件，双击运行，不需要安装，也不会在它旁边生成任何文件。

系统要求：Windows 10/11 ＋ Microsoft Edge WebView2 运行时（Win11 与装了 Edge 的机器都有）。
不需要管理员权限。

> 首次运行未签名程序时，Windows 可能提示「无法验证发布者」，点「运行」即可；此后再打开不再提示。

## v1.4 修复：设置页「移除全部端口并还原」终于真正可用

**现象**：点「移除全部端口并还原」，确认后只会弹出「正在处理上一个操作，请稍候」——这个设置页的核心按钮从来没有真正工作过。

**原因**：`reset()` 先把 busy 标记置为 true，再调用 `applyAll()`；而 `applyAll()` 的第一行就是忙碌守卫，直接拒绝。更糟的是端口列表在拒绝**之前**已经就地清空：界面显示零端口、state.json 未保存、内核监听还在，三者不一致。

**修法**：

- busy 交给 `applyAll` 自己管理，reset 不再手动置位；失败时端口列表从 state.json 恢复；
- 顺带修复了 `applyAll` 回滚路径的一个潜在 bug：回滚链里的兜底请求若也失败，busy 会被永久卡死，之后所有操作都报「正在处理上一个操作」；
- 改选节点失败时恢复到之前选中的节点，不再把原节点抹掉。

## v1.4 其它改进

- **安全**：界面加了 Content-Security-Policy（脚本仅限同源）；`pipe.status` 不再把内核 secret 回传前端；端口探测列表加上界。
- **更快**：管道发现并行探测（Verge 未启动时等待时间从「候选数 × 1.5 秒」降到最多 1.5 秒）；逐端口回读组状态改为并行。
- **更稳**：节点下拉的监听器泄漏修复（长会话不再累积）；日志超过 2MB 自动截断；原子写并发安全；`vergeRunning` 状态实时化。
- **首启容错**：内核 secret 先于管道发现就位，消除「内核校验管道凭据时首次发现必然失败」的自举死锁。
- Go 侧首次有了单元测试（管道 HTTP 解析边界 17 项）；单元测试 49 → 54 项。

## 上手三步

1. 打开 `PortPilot.exe`（会自动检测正在运行的 Clash Verge）；
2. 「端口」页新建一个端口，比如 `10801`；
3. 拨开它的开关，在「节点」页选一个节点 —— 这个端口就能代理流量了。

## 亮点

- **单文件 exe**：界面与依赖全部内嵌，取它一个文件即可运行。
- **打开就是真的在监听，关闭就真的停止监听**；关窗退出后端口继续可用。工具本身不常驻：无托盘、无服务、无定时轮询。
- **选节点即时生效**：不写文件、不重载内核、不断开已有连接。
- **TUN 兼容**：下发前把 `tun:` 段按内核运行值做平，开着 TUN 开关端口不闪断；TUN 被静默关闭时自动补回。
- **订阅更新自愈**：节点改名不再打不开端口，失效的重新选一下就好。
- **重启 Clash Verge 后依然有效**：端口定义与节点选择写进当前订阅的扩展模板，Verge 每次重新生成配置都会带上，节点选择由内核的 store-selected 还原。
- **写入前备份、失败自动回滚**：内核拒绝的配置不会落盘；模板被 Verge 界面改写后也会自愈。
- **启动失败说得清**：出错会写日志并弹框说明原因，不会静默退出。
- 端口只听 `127.0.0.1`：不需要管理员权限，也不会触发防火墙提示。

## 验证

- 54 项单元测试：`node --test`（新增 reset 与 selectNode 回退的回归测试）
- Go 单元测试 17 项：`go test`（管道 HTTP 解析、原子写、日志轮转、端口探测）
- 宿主自检：`PortPilot.exe --selftest`
- 真机端到端：`node tests/e2e-pipeline.js 10809`

## 已知限制

- 端口跟随**当前订阅**：在 Verge 里切换订阅后，端口会随新订阅重建（工具运行时会自动补一次）。
- 仅支持 Windows。
