不常驻的 Windows 桌面工具：把 Clash Verge Rev 订阅里的节点各自开放成一个本地代理端口。

## 下载

- **PortPilot-v1.3-windows-amd64.exe** —— 单个文件，双击运行，不需要安装，也不会在它旁边生成任何文件。

系统要求：Windows 10/11 ＋ Microsoft Edge WebView2 运行时（Win11 与装了 Edge 的机器都有）。
不需要管理员权限。

> 首次运行未签名程序时，Windows 可能提示「无法验证发布者」，点「运行」即可；此后再打开不再提示。

## v1.3 修复：订阅更新后节点改名，所有端口一起打不开

**现象**：订阅更新后，总览页报「有 1 个端口没有成功打开：10801，请检查端口号是否被占用」，但 10801 的端口号明明是空闲的；内核日志里真正的错误是 `proxy group[N]: PortPilot-xxxx: '旧节点名' not found`。

**原因**：每个端口保存的节点名会随订阅更新失效（改名或删除）。旧版本把它照写进组默认值（`proxies: ["旧节点名"]`），而内核校验组成员时会让**整份配置** 400 拒绝——所有端口一起失败，与端口号是否被占用毫无关系；连关着的端口里存的失效节点也会挡住别的端口。

**修法**：

- 应用配置时，把不在当前订阅里的节点名从组默认值中丢弃，组靠 `include-all-proxies` 仍可正常使用，不再挡住任何端口；
- 失败提示按真实原因拆分：节点失效的引导到「节点」页重新选择，剩下的才提示检查端口占用；端口行状态明细同步修正；
- 运行记录新增「节点失效提醒」，列出哪些端口的节点需要重选（开/关状态都会提醒）；
- 修复运行记录并发写入互相覆盖的竞争。

## 上手三步

1. 打开 `PortPilot.exe`（会自动检测正在运行的 Clash Verge）；
2. 「端口」页新建一个端口，比如 `10801`；
3. 拨开它的开关，在「节点」页选一个节点 —— 这个端口就能代理流量了。

## 亮点

- **单文件 exe**：界面与依赖全部内嵌，取它一个文件即可运行。
- **打开就是真的在监听，关闭就真的停止监听**；关窗退出后端口继续可用。工具本身不常驻：无托盘、无服务、无定时轮询。
- **选节点即时生效**：不写文件、不重载内核、不断开已有连接。
- **TUN 兼容**：下发前把 `tun:` 段按内核运行值做平，开着 TUN 开关端口不闪断；TUN 被静默关闭时自动补回。
- **订阅更新自愈**：节点改名不再打不开端口，失效的重新选一下就好。
- **重启 Clash Verge 后依然有效**：端口定义与节点选择写进当前订阅的扩展模板，Verge 每次重新生成配置都会带上，节点选择由内核的 store-selected 还原。
- **写入前备份、失败自动回滚**：内核拒绝的配置不会落盘；模板被 Verge 界面改写后也会自愈。
- **启动失败说得清**：出错会写日志并弹框说明原因，不会静默退出。
- 端口只听 `127.0.0.1`：不需要管理员权限，也不会触发防火墙提示。
- 不依赖、不读取、不在界面提及任何既有的自定义脚本。

## 验证

- 49 项单元测试：`node --test`（新增失效节点丢弃与失效提醒的回归测试）
- 宿主自检：`PortPilot.exe --selftest`
- 真机端到端：`node tests/e2e-pipeline.js 10809` 18 项全部通过
- 真机对照验证：同一份「含失效节点」的状态，旧逻辑在真实内核上被整份 400 拒绝，新逻辑应用成功且端口正常监听

## 已知限制

- 端口跟随**当前订阅**：在 Verge 里切换订阅后，端口会随新订阅重建（工具运行时会自动补一次）。
- 仅支持 Windows。
